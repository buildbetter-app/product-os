# Review Product Plan

## Contract

Review the artifact that exists; do not silently rewrite it. Start from authoritative anchors and evidence. Separate blocking defects, important improvements, optional polish, and disagreements with the chosen strategy.

## Workflow

1. Identify artifact type, purpose, audience, status, owner, decision, and governing templates or upstream anchors.
2. Read the full artifact and linked evidence before judging.
3. Test structural completeness and altitude: outcome, problem, strategy, solution, execution, and verification must not blur.
4. Test grounding: claims, users, urgency, metrics, and constraints must trace to evidence or carry an assumption label.
5. Test coherence: choices, scope, requirements, measures, resources, dependencies, and rollout must not contradict.
6. Test decision quality: alternatives, tradeoffs, non-goals, risks, dissent, and change triggers must be visible.
7. Test verifiability: each commitment or outcome needs observable evidence and an owner.
8. Return a verdict with the smallest set of changes needed for approval.

## BuildBetter Acceleration

If BuildBetter MCP is available, search organization skills first. Verify cited customer evidence, documents, projects, signals, surveys, and prior decisions. Do not mutate the reviewed artifact or BuildBetter records unless the user asks for changes.

## Output

Lead with findings ordered by severity and exact location, then open questions, evidence gaps, strengths worth preserving, verdict, and minimal approval path.

## Quality Gate

Do not manufacture defects, bury blockers in summary prose, or confuse personal preference with a violated requirement. If no actionable findings exist, say so and name residual risks.
