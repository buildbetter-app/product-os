# Naming standard

Product OS uses one canonical, verb-led name per user outcome.

## Rules

1. Use lowercase kebab-case and stay under 64 characters.
2. Start with an action: plan, define, shape, synthesize, map, validate, prioritize, size, design, write, scope, align, verify, run, review, evaluate, or manage.
3. Name the durable product task, not a framework. For example, use shape-product-strategy rather than strategy-kernel.
4. Keep source-specific adapters out of the generic name. BuildBetter-exclusive skills use a buildbetter- prefix in BB-Skills.
5. Merge synonyms when they lead to the same decision artifact. Split skills only when their trigger, workflow, output, or safety boundary is materially different.
6. Avoid advisor, helper, framework, toolkit, process, and workflow suffixes unless the noun is the actual user intent.

## Normalization examples

| Source names | Product OS name |
| --- | --- |
| strategy-doc, create-strategy, defining-product-strategy, product-strategy | shape-product-strategy |
| prd-writing, create-prd, writing-prds, prd-development | write-product-requirements |
| research-synthesis, summarize-interview, analyzing-user-feedback | synthesize-customer-research |
| roadmap-planning, roadmap-prioritization, outcome-roadmap | plan-outcome-roadmap |
| experiment-design, product-experiments, ab-test-analysis | design-product-experiment |
| launch-plan, launch-planning, gtm-strategy | plan-product-launch |

The frontmatter name must exactly match the folder. Display names may use title case.
